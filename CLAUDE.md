# Corehold

Single-tower idle defense for Android/iOS, portrait, one finger. Working title; bundle id `com.virabyan.corehold`.

## Hard rules
- The user never opens the Unity editor. Everything is created from C# at runtime; run Unity **only in batch mode**.
- `Assets/Scenes/Main.unity` contains exactly one object, `Bootstrap`. Do not add objects or prefabs to scenes.
  The scene is generated by `ProjectSetup.Run`; rerun it instead of editing the scene file.
- Visuals are plain generated shapes (`Shapes.cs`) until art is requested.
- All balance numbers live in `Assets/Resources/balance.json`; formulas live in `Formulas` in `Assets/Scripts/Balance.cs`.
  No tuning constants in gameplay code.
- Enemies and projectiles are pooled plain C# objects updated by `Game.Update` — no per-enemy MonoBehaviour,
  no Instantiate/Destroy or allocations during play. Performance target: 200 enemies at 60 fps on a low-end Android phone.
- Out of scope until the core is proven fun: ads, IAP, analytics, saves, meta progression.
- After every meaningful change: compile in batch mode, read the log, fix all errors, run tests, then commit.

## Tools
- Unity 6000.6.5f1: `C:\Program Files\Unity\Hub\Editor\6000.6.5f1\Editor\Unity.exe`
- Unity Hub (CLI): `"D:\Unity\Unity Hub\Unity Hub.exe" -- --headless <command>`
- Android SDK/NDK/JDK: the ones installed by Unity Hub with the editor's Android module.
- Shell: PowerShell. Set `$u = "C:\Program Files\Unity\Hub\Editor\6000.6.5f1\Editor\Unity.exe"` first.
  Unity must not have the project open elsewhere, or batch mode fails with "another Unity instance is running".

## Commands (run from the project root `D:\Corehold`)
Use `-logFile <file>` and read the file; `Start-Process -Wait` makes PowerShell wait for Unity to exit.

```powershell
# Compile (imports, compiles scripts, exits). Errors: search the log for "error CS" and "Compilation failed".
Start-Process $u -ArgumentList '-batchmode','-quit','-nographics','-buildTarget','Android','-projectPath','.','-logFile','Logs/compile.log' -Wait -PassThru | % ExitCode

# Re-apply player settings and regenerate the bootstrap scene
Start-Process $u -ArgumentList '-batchmode','-quit','-nographics','-buildTarget','Android','-projectPath','.','-executeMethod','ProjectSetup.Run','-logFile','Logs/setup.log' -Wait -PassThru | % ExitCode

# Tests (no -quit with -runTests). Results are NUnit XML.
Start-Process $u -ArgumentList '-batchmode','-nographics','-projectPath','.','-runTests','-testPlatform','EditMode','-testResults','TestResults/editmode.xml','-logFile','Logs/editmode.log' -Wait -PassThru | % ExitCode
Start-Process $u -ArgumentList '-batchmode','-nographics','-projectPath','.','-runTests','-testPlatform','PlayMode','-testResults','TestResults/playmode.xml','-logFile','Logs/playmode.log' -Wait -PassThru | % ExitCode

# Debug APK  -> Builds/Android/Corehold-debug.apk   (development build)
Start-Process $u -ArgumentList '-batchmode','-quit','-buildTarget','Android','-projectPath','.','-executeMethod','BuildScript.BuildAndroidDebug','-logFile','Logs/build.log' -Wait -PassThru | % ExitCode
# Perf APK   -> Builds/Android/Corehold-perf.apk    (non-development, use for fps checks)
Start-Process $u -ArgumentList '-batchmode','-quit','-buildTarget','Android','-projectPath','.','-executeMethod','BuildScript.BuildAndroidPerf','-logFile','Logs/build.log' -Wait -PassThru | % ExitCode

# Install on a USB-connected phone
adb install -r Builds/Android/Corehold-debug.apk
```

## Layout
- `Assets/Scripts/` (assembly `Corehold`)
  - `Bootstrap.cs` — the scene's only component; creates camera, `Game`, UI.
  - `Game.cs` — run state, waves, enemies, tower targeting/shooting, projectiles, coins, upgrades.
  - `Pools.cs` — `Enemy`, `Projectile`, generic `Pool<T>` (prewarmed, swap-remove active list).
  - `Balance.cs` — data classes for `balance.json` + `Formulas`.
  - `Shapes.cs` — generated circle/ring/square sprites.
  - `GameUI.cs`, `UIFactory.cs` — HUD, upgrade buttons, result screen, debug overlay (fps, enemies, wave, stress toggle).
- `Assets/Editor/` — `ProjectSetup.cs` (player settings + scene), `BuildScript.cs` (APK builds).
- `Assets/Tests/EditMode` — balance/formula tests. `Assets/Tests/PlayMode` — full sped-up run through the real UI, stress test.

## Conventions
- Namespace `Corehold`. Editor scripts in the global namespace so `-executeMethod ClassName.Method` stays short.
- UI is uGUI built in code with the legacy `Text` and built-in `LegacyRuntime.ttf`, reference resolution 1080x1920.
  UI object names (`Upgrade_Damage`, `RestartButton`, `StressButton`, `ResultPanel`) are used by tests; keep them stable.
- World: tower at origin; camera keeps `run.worldHalfWidth` visible horizontally.
- Stress mode (debug button) keeps exactly `Game.StressEnemyCount` enemies alive and makes the tower invulnerable.
- Commit at every working milestone with a descriptive message.
