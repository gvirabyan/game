# Corehold

Path-based tower defense for Android/iOS, landscape, one finger. Enemies (soldier, jeep, drone, tank, apc, heli, boss) walk a
winding road to the base (HQ); leaks cost lives, 0 lives = level failed. The player builds/upgrades/sells 8 towers (mg, cannon,
aa, flame, tesla, mortar, sniper, cryo) on pads. Two modes: a 100-mission campaign (generated by `Campaign.cs` from `campaign` in balance.json: 4 zones of 25 - grass,
desert, snow, autumn; a new enemy every 5 missions, a boss every 10th, towers unlock along the way; missions unlock in order)
and Endless. Progress (stars, endless best, mute) is saved with PlayerPrefs in `Progress.cs`.
Working title; bundle id `com.virabyan.corehold`. The user asked for chat replies in Russian.

## Hard rules
- The user never opens the Unity editor. Everything is created from C# at runtime; run Unity **only in batch mode**.
- `Assets/Scenes/Main.unity` contains exactly one object, `Bootstrap`. Do not add objects or prefabs to scenes.
  The scene is generated by `ProjectSetup.Run`; rerun it instead of editing the scene file.
- 3D view: game logic is flat 2D map coordinates (x, y) exactly as levels are authored. A perspective
  camera (`View.Pitch`, `View.FieldOfView`) is fitted by `CameraRig.Fit` to `CameraRig.PlayArea`; map Z scale is `View.ZStretch`
  (now 1: world = map, so range decals are true circles on the ground). Fog, vignette, wrap lighting + rim + hit flash live in LowPoly.shader. Convert with
  `View.World` (positions) / `View.Yaw` (facing); flat ground/road are built in map coords under
  `View.GroundTransform`. Taps raycast the ground plane and divide z by ZStretch.
- No external art: low-poly meshes are built in code (`Art/Models.cs` via `MeshBuilder`) with vertex colours and ONE
  material (`Resources/Shaders/LowPoly.shader`, GPU instancing; vertex alpha < 1 = glow). The whole static level is
  one combined mesh. UI icons/panels are SDF sprites in one runtime atlas (`Art/Art.cs`, `Atlas.cs`).
- Font: Russo One (SIL OFL, `Resources/Fonts`, license file next to it) for Latin/Cyrillic; system fonts for hy/zh/ja/ko.
  Never hard-code UI text: add a key to localization.json (all languages, same {n} placeholders; a test checks). Project colour space is Gamma.
- All balance numbers AND level layouts (path waypoints, pads, waves) live in `Assets/Resources/balance.json`;
  formulas live in `Formulas` in `Assets/Scripts/Balance.cs`. The EditMode geometry test validates pads vs road/screen.
  No tuning constants in gameplay code.
- Enemies, projectiles and effects are pooled plain C# objects updated by `Game.Update` — no per-enemy MonoBehaviour,
  no Instantiate/Destroy or allocations during play. Performance target: 200 enemies at 60 fps on a low-end Android phone.
- Out of scope: ads, IAP, analytics. The only save is campaign progress (`Progress.cs`, PlayerPrefs).
- After every meaningful change: compile in batch mode, read the log, fix all errors, run tests, then commit.

## Commands
All paths absolute; Unity resolves relative `-logFile`/`-testResults` paths unreliably. `Start-Process -Wait -PassThru`
makes PowerShell wait for Unity and gives the exit code. Always read the log afterwards.
A `[Licensing::Module] Error: Access token is unavailable` line in logs is harmless.

```powershell
$u = "C:\Program Files\Unity\Hub\Editor\6000.6.5f1\Editor\Unity.exe"; $P = "D:\Corehold"

# Compile only. Check: Select-String $P\Logs\compile.log -Pattern "error CS|Compilation failed"
(Start-Process $u -ArgumentList '-batchmode','-quit','-nographics','-buildTarget','Android','-projectPath',$P,'-logFile',"$P\Logs\compile.log" -Wait -PassThru).ExitCode

# Re-apply player settings and regenerate the bootstrap scene (also compiles)
(Start-Process $u -ArgumentList '-batchmode','-quit','-nographics','-buildTarget','Android','-projectPath',$P,'-executeMethod','ProjectSetup.Run','-logFile',"$P\Logs\setup.log" -Wait -PassThru).ExitCode

# Tests (never pass -quit with -runTests). NUnit XML in TestResults\. PlayMode takes ~1 min.
(Start-Process $u -ArgumentList '-batchmode','-nographics','-projectPath',$P,'-runTests','-testPlatform','EditMode','-testResults',"$P\TestResults\editmode.xml",'-logFile',"$P\Logs\editmode.log" -Wait -PassThru).ExitCode
(Start-Process $u -ArgumentList '-batchmode','-nographics','-projectPath',$P,'-runTests','-testPlatform','PlayMode','-testResults',"$P\TestResults\playmode.xml",'-logFile',"$P\Logs\playmode.log" -Wait -PassThru).ExitCode
# Summary: [xml]$x = Get-Content $P\TestResults\playmode.xml; $x.'test-run' | select result,total,passed,failed

# Debug APK -> Builds\Android\Corehold-debug.apk (development build). Check the log for "[BuildScript] Succeeded".
(Start-Process $u -ArgumentList '-batchmode','-quit','-nographics','-buildTarget','Android','-projectPath',$P,'-executeMethod','BuildScript.BuildAndroidDebug','-logFile',"$P\Logs\build-debug.log" -Wait -PassThru).ExitCode
# Perf APK  -> Builds\Android\Corehold-perf.apk (non-development; use this one to judge fps)
(Start-Process $u -ArgumentList '-batchmode','-quit','-nographics','-buildTarget','Android','-projectPath',$P,'-executeMethod','BuildScript.BuildAndroidPerf','-logFile',"$P\Logs\build-perf.log" -Wait -PassThru).ExitCode

# Screenshots on PC without a phone (needs graphics: no -nographics). PNGs in Logs\Screens\ (menu, level1-3).
(Start-Process $u -ArgumentList '-batchmode','-projectPath',$P,'-runTests','-testPlatform','PlayMode','-testFilter','Corehold.Tests.ScreenshotTests','-testResults',"$P\TestResults\screens.xml",'-logFile',"$P\Logs\screens.log" -Wait -PassThru).ExitCode

# Install on the user's phone (Realme RMX3834, Wi-Fi debugging; port changes after reconnects: adb mdns services, adb connect IP:PORT)
adb install -r D:\Corehold\Builds\Android\Corehold-debug.apk
adb shell am start -n com.virabyan.corehold/com.unity3d.player.UnityPlayerGameActivity
# Screenshot to check visuals: adb shell screencap -p /sdcard/s.png; adb pull /sdcard/s.png <scratchpad>
# Taps: adb shell input tap X Y (screen 1600x720 landscape). 'adb shell sleep' does not wait on this phone; use Start-Sleep.
# The user often plays on the phone at the same time: do not send taps unless asked; screenshots are fine.
# Unity builds/tests start Unity's own adb, which kills Android Studio's adb server: reconnect afterwards.
```

## Layout
- `Assets/Scripts/` (assembly `Corehold`)
  - `Bootstrap.cs` — the scene's only component; builds art, perspective camera (fitted by CameraRig), sun, ambient, fog, `Game`, UI.
  - `Game.cs` — state machine (Menu/Playing/Won/Lost), level load, waves, enemies on path, towers, projectiles, effects, taps.
  - `LevelView.cs` — `View` (2.5D mapping), `Layers`, builds the combined static level mesh (ground, road, pads, HQ, decor).
  - `Pools.cs` — `Enemy`, `Projectile`, `Effect`, `Tower`, `BuildSpot`, `LevelPath`, generic `Pool<T>`.
  - `Balance.cs` — data classes for `balance.json` + `Formulas`. `Campaign.cs` — generates the 100 missions.
  - `Loc.cs` + `Resources/localization.json` — UI text in 16 languages (keys ui.*, zone.*, tower.<id>, enemy.<id>[.info]).
    Armenian/CJK use phone system fonts. Changing language rebuilds the UI (`GameUI.Rebuild`). Settings: `SettingsButton`, `Lang_<code>`.
  - `Progress.cs` — saved progress. `Art/Biomes.cs` — zone palettes and vegetation.
  - `Art/Models.cs`, `Art/MeshBuilder.cs` — low-poly 3D models (towers per level, enemy rigs). `Art/Icons.cs` — UI icons
    rendered from the 3D models at startup (atlas fallback without a GPU). `Art/Art.cs`, `Art/Atlas.cs` — UI sprites/icons atlas.
  - `GameUI.cs`, `UIFactory.cs` — menu, HUD, build/tower panels, pause, result, debug overlay (fps, enemies, stress toggle).
  - `Audio/Sounds.cs` — every sound and both music loops synthesised at startup (no audio files).
    `Audio/Sfx.cs` — voice pool with per-clip throttling, music crossfade, mute.
  - `WorldMapView.cs` — main menu: scrollable 3D campaign map (green/desert/snow), one marker per mission, convoy and
    helicopter animation. GameUI keeps the `Level_N` buttons glued to the markers and opens a mission card (`PlayButton`).
- `Assets/Editor/` — `ProjectSetup.cs` (player settings + scene), `BuildScript.cs` (APK builds).
- `Assets/Tests/EditMode` — balance + level geometry. `Assets/Tests/PlayMode` — lose/retry, build/upgrade/sell,
  win all levels with full defense, 200-enemy stress (PlayMode takes ~3 min).

## Conventions
- Namespace `Corehold`. Editor scripts in the global namespace so `-executeMethod ClassName.Method` stays short.
- UI is uGUI built in code with the legacy `Text` (Russo One font), reference resolution 1920x1080,
  rounded panels use the sliced `Art.Panel` sprite. Object names used by tests — keep them stable:
  `ModeEndless`, `Level_1..100`, `PlayButton`, `IntroOk` (new enemy/tower card), `WaveBar`, `WaveButton`, `BuildPanel`, `Build_<towerId>`, `TowerPanel`, `UpgradeButton`, `SellButton`,
  `ResultPanel`, `RetryButton`, `NextLevelButton`, `MenuButton`, `PauseButton`, `ResumeButton`, `SpeedButton`, `StressButton`.
- Level coordinates (landscape): x in -8.5..8.5, pads in y -4.7..3.6 (HUD row on top). Canvas reference 1920x1080,
  scaled by height. The wave button sits in the HUD row; build/tower panels open on the screen side away from the pad. The first path point is
  extended off-screen automatically; the last one is the HQ.
- Roads are off-road dirt tracks (`DirtRoad` in LevelView.cs) along `LevelPath.Rounded` paths: corners are curved
  and enemies follow the curves; pad clearance is tested against the rounded path.
- Tower attack kinds (`attack` in balance.json): projectile (bullet/shell/missile/flame/mortar arc), chain (tesla),
  instant (sniper), pulse (cryo slow). Enemies can burn, be slowed, and drop units on death (`spawnOnDeath`).
- Units are animated from parts (soldier legs, tank turret, drone rotors) set up by `Game.SetupParts`; pooled enemies
  keep their part objects and only swap meshes. The first wave starts by itself after `economy.firstWaveDelay`.
- Towers change look per level: `Models.TowerBase(level)` / `Models.Turret(id, level)`, swapped on upgrade.
- Camera: pinch (or mouse wheel) zooms up to `Game.MaxZoom`, one-finger drag pans when zoomed; a tap is a press
  that ends without moving. `Game.Zoom` is exposed for screenshots.
- Stress mode keeps exactly `Game.StressEnemyCount` enemies walking (leaks loop back to the start, no lives lost).
- Commit at every working milestone with a descriptive message.
